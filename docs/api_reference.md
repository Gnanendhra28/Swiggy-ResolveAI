# Swiggy ResolveAI — Reconciled API Contract Reference

This document serves as the authoritative, cryptographically verified API specification for all endpoints registered on the **Swiggy ResolveAI** FastAPI application.

- **Base URL**: `/api/v1` (with top-level health aliases `/health`, `/health/live`, `/health/ready`)
- **Specification Format**: OpenAPI 3.1.0 / JSON
- **Registered Route Counts**:
  - **32 OpenAPI Documented Paths** (29 `/api/v1/` routes + 3 `/health*` top-level aliases)
  - **40 Total Registered Starlette APIRoutes and System Routes** (32 core endpoints + 3 trailing slash aliases + 1 root redirect + 4 documentation/schema routes)
- **Default Headers**:
  - `Content-Type: application/json`
  - `X-Correlation-ID: <uuid>` (Optional; automatically generated by middleware if omitted)
  - `Authorization: Bearer <token>` (Required for privileged operational actions)

## 2. Authentication & Authorization Specification (Workstream 1)

### 2.1 Demonstration Token Endpoint
- **Method**: `POST`
- **Path**: `/api/v1/auth/dev-token`
- **Security**: Strictly active when `ENVIRONMENT=development`. Returns `HTTP 403 Forbidden` in `staging` and `production`.
- **Request Body**:
```json
{
  "operator_profile": "ops_lead"
}
```
*Supported predefined profiles: `"ops_lead"`, `"admin"`, `"operator"`, `"supervisor"`, `"intern"`.*
- **Response**: `200 OK`
```json
{
  "access_token": "eyJhbGciOiAiSFMyNTYiLCAidHlwIjogIkpXVCJ9...",
  "token_type": "bearer",
  "operator_identity": "dev_ops_lead_console",
  "operator_role": "OPS_LEAD",
  "expires_in_seconds": 7200,
  "environment": "development",
  "warning": "DEVELOPMENT ONLY: This token generator is strictly disabled in staging and production."
}
```

### 2.2 Authenticated Approval Gate
- **Method**: `POST`
- **Path**: `/api/v1/intelligence/recommendations/{recommendation_id}/approve`
- **Headers**:
  `Authorization: Bearer <valid_signed_token>`
- **Request Body**:
```json
{
  "notes": "Verified kitchen prep backlog; approved courier dispatch escalation."
}
```
- **Privilege Enforcement**:
  - Requires signed Bearer token with claim `role` $\in \{$`"OPS_LEAD"`, `"ADMIN"`, `"SUPERVISOR"`$\}$.
  - Submitting `"operator_role": "OPS_LEAD"` in the JSON body without a signed token is rejected with `HTTP 403 Forbidden`.
  - In `staging` or `production`, missing `Authorization` header returns `HTTP 401 Unauthorized`.

## 3. Execution Mode Boundaries

The backend enforces `EXECUTION_MODE` (`SIMULATION`, `SHADOW`, `LIVE`):
- **`SIMULATION`**: Executes simulated recovery actions, sets `is_simulated = True`, and records `RecoveryExecutionAudit`. Fails at startup if `ENVIRONMENT=production`.
- **`SHADOW`**: Operates in passive evaluation only. `POST /api/v1/intelligence/recommendations/{id}/execute` returns `HTTP 403 Forbidden` (`"Recovery execution rejected: system is running in read-only SHADOW mode."`).
- **`LIVE`**: Strictly disabled by governance policy. Application fails safely at startup across all environments.
